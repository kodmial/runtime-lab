# Agent execution and handoff — current knowledge

## Confirmed
- `automation/knowledge/` is the durable memory boundary between short-lived agents.
- Every automated issue run reads the protocol, relevant topic notes, and prior relevant experiment records before changing code.
- Every run writes one unique experiment record before finishing.
- Unique per-run files avoid conflicts between parallel agents; topic notes are curated current knowledge, not diaries.
- OpenCode issue execution must not modify `.github/workflows/**`; workflow envelopes are maintained separately.
- Git/branch/commit/PR orchestration belongs to the workflow.
- Observations, interpretations, and decisions are recorded separately so old hypotheses are not inherited as facts.
- Discover history with the derived catalog first: `python automation/knowledge_catalog.py query --issue <N> | --topic <slug> | --outcome <succeeded|failed|inconclusive> | --record-id <id>` (filters compose, offline, deterministic). Then read only the matching full records; the catalog never replaces a record as evidence. Evidence: `../experiments/issue-34-run-36410184254.md`.
- Experiment front matter is strict JSON (see `../schema/experiment.json`); filename, `issue`, `run_id`, and `record_id` must agree. Never commit a generated catalog file; `build` writes to stdout or an explicit temp/cache path. Evidence: `../experiments/issue-34-run-36410184254.md`.
- Private long-term knowledge lives in `kodmial/agent-knowledge` (`schema/` + `projects/<project>/experiments|topics|decisions`) with GitHub Issues enabled (`has_issues=true`) for the repo-native Knowledge Plane roadmap; ephemeral workers receive only selected knowledge via `automation/knowledge_store.py:build_worker_context` and never receive `TAP_PAT`/App tokens. Normal access uses short-lived App installation tokens scoped to the knowledge repo (`metadata:read` + `contents:write`); writes use bounded optimistic CAS, experiment paths are immutable, and topic conflicts merge explicitly. Bootstrap uses `POST /user/repos` (`kodmial` is a personal account, never `/orgs/*`) with `private=true` and `has_issues=true`; settings corrections use the minimal `{"has_issues": True}` PATCH that never touches visibility, verified by `verify_knowledge_repo_settings_for_roadmap`. In Actions the PAT arrives as `GH_TOKEN`/`GITHUB_TOKEN`, so decide by live capability probe, not literal `TAP_PAT` presence or token format. Live bootstrap completed and verified private with layout, trusted read/write, and #34-compatible migration; settings correction to enable Issues applied and verified private. Evidence: `../experiments/issue-37-run-36416685324.md` (supersedes `../experiments/issue-37-run-36413374778.md`, which supersedes `../experiments/issue-37-run-36411929515.md`).
- Roadmap administration baseline for `kodmial/agent-knowledge` (verified live): `priority:p0` on #1-#4, `priority:p1` on #5-#9, `priority:p2` on #10-#13, with the exact native `blockedBy` DAG #2<-#1, #3<-#2, #4<-#3, #5<-#4, #6<-#5, #7<-#6, #8<-#5,#6, #9<-#6,#8, #10<-#7,#9, #11<-#4,#9, #12<-#7,#8,#9, #13<-#12 (acyclic, repo still private). Administer idempotently with `gh label create` plus `gh issue edit --add-label/--add-blocked-by`; verify via REST labels plus GraphQL `blockedBy(first:N) { nodes { number } }` (`gh issue view --json` exposes no `blockedBy` field) plus authenticated privacy view and anonymous-404 check. Evidence: `../experiments/issue-44-run-36417650618.md`.
- Private-store review repairs (issue #39, verified live plus 350-test suite): CAS `refresh_fn` re-checks immutability/expected-version on every attempt (no silent overwrite on stale-head retry); listing fails closed when the backend cannot enumerate; production reads/writes go through `GitHubApiKnowledgeBackend` (Contents reads, Git-database CAS writes with `force=false`; `DictGitHubBackend` stays tests-only); the trusted controller optionally enriches tasks via `render_trusted_task_text` (credential-free, bounded, fail-closed); worker child processes run with a scrubbed env (no `TAP_PAT`/`GH_TOKEN`/`GITHUB_TOKEN`/App keys) in both `knowledge_store` and `opencode_runner`/`runner_server`. The live store still holds only the original 8 migrated records (newer local records validated offline, mirroring left as follow-up record administration). Evidence: `../experiments/issue-39-run-36431056826.md`.
- Runtime Lab -> `kodmial/agent-knowledge` replication is automatic: `.github/workflows/knowledge-sync.yml` runs on knowledge changes and is explicitly dispatched after automatic merges, invoking `automation/knowledge_sync.py`. Experiment records are create-or-identical, topic updates are guarded by the last successful `.sync-state.json` hashes, and independent central edits fail closed instead of being overwritten. The sync script is orchestration-neutral so Continuum can invoke the same hook later.
