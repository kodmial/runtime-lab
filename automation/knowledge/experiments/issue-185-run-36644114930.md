# Fix the finalize-mirror budget nesting on fourth live hold proof (repair run 36642218343)

## Hypothesis / objective

Run 36642218343 (source issue #106, smoke) failed in `render-job.sh` at the
exact-artifact pre-creation gate with `infrastructure-blocked` for the retired
artifact `11001896223` (workflow run `36492639568`) plus the known-artifact

## Interpretation

- The execute=failure outcome for run 36642218343 is the executor gate
  working correctly at HEAD, not a lifecycle defect: no worker could
  honestly test what #106 requires, so refusing pre-creation in seconds
  at zero cost is the only honest behavior.
- The reusable defect fixed here is mirror fidelity, not signal or
  exposure: the retirement answer now exists in seven automation-side
  forms (eligibility mirror, log verdict, structured record key, hold
  CLI, branch library, notice formatter, executable `--finalize` -- all
  proven live or offline against real failure bytes) and the provisioned
  envelope still calls none of them. Before the next adoption window,
  the mirror must match the envelope exactly, or adoption trades one
  divergence for another: at/over budget with an open repair, the old
  helper said `duplicate` where the envelope says `exhausted`.
- The budget observation bounds the loop independently of adoption:
  identical held-superseded refusals each consumed one of 10 budgeted
  repairs without ever testing anything, and the budget is now spent, so
  the next identical redispatch pauses with the exhausted notice instead
  of minting. A future repair-budget design should distinguish
  deterministic pre-creation refusals (nothing tested) from executed
  attempts, but that redesign is provisioned-envelope work, not this
  repair.

## Reusable knowledge

- A complete automation-side answer is still not a fix while the
  provisioned consumer never calls it: run 36642218343 executed at a
  base containing the full guard/log/record/CLI/library/`--finalize`
  chain, every link fired correctly on its live bytes, and finalize
  still minted #185. Ship consumer branches as executable CLIs AND keep
  them bit-faithful to the envelope text they mirror, or adoption
  inherits the divergence.
- Nesting is behavior: the envelope reports `exhausted` (not
  `duplicate`) when budget is spent even with an open repair. Any
  executable mirror must nest the open-repair check inside the budget
  check, or it disagrees exactly when the budget runs out -- which is
  when the next #106-class redispatch arrives.
- Count what refusals cost: deterministic pre-creation refusals that
  test nothing consumed the full 10-repair budget one mint at a time.
  Future budget designs should separate "nothing was tested" refusals
  from executed attempts; until then the exhausted branch is the loop's
  backstop.
