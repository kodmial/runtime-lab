# Repair qualification-chain GH_TOKEN envelope-escape 401 class (offline half)

## Hypothesis / objective

Qualification-chain run 36508937033 fails in `Reconcile qualification state`
with 401 "Bad credentials" because the workflow envelope sets
`GH_TOKEN: \${{ secrets.TAP_PAT || github.token }}` (escaped GitHub
expression), so the runner receives the evaluated secret with a stray leading
backslash as the effective credential. Objective: repair the credential path
without touching `.github/workflows/**` (stable envelopes are provisioned
separately; this token cannot push workflow files), without changing
qualification semantics or objective state logic, add a static regression
guard, and leave an exact deterministic post-merge proof procedure so the
chain can be woken explicitly for #140/#141.

## Interpretation

- The 401 class is explained by the envelope defect: the evaluated secret arrives with a leading backslash and GitHub rejects it as bad credentials. Stripping exactly one leading backslash at the consumer restores the real credential for `qualification_chain.js` without altering any qualification decision, state shape, or dispatch behavior.
- The consumer hardening covers the qualification-chain reconcile path; the two `docker-qualification.yml` `GH_TOKEN` lines feed the `gh` CLI directly from the envelope and cannot be shimmed from `automation/`, so they remain broken until the separate envelope provisioning removes the escaping. The guard CLI failing closed on the live tree today is the correct signal, not a regression.
- The new pytest file stays green because its live-tree test asserts detection of the 3 known envelope lines (envelope-provisioning tracker), while the guard CLI itself is the artifact that "fails if production workflow credential env values contain escaped syntax". After the envelope is provisioned, that test must be updated to assert an empty finding list.
- Live proof (reading issue comments without 401 after merge, plus explicit wake for #140/#141) cannot be produced from this credential-less sandbox and is honestly deferred; hence the `inconclusive` outcome rather than a premature `succeeded`.

## Reusable knowledge

- An escaped `\${{ ... }}` workflow expression corrupts `GH_TOKEN` with a leading backslash and yields 401 "Bad credentials"; real tokens never start with a backslash, so consumers may strip exactly one while failing closed on empty/unexpanded values.
- A static credential guard must scope to credential env fields only (`GH_TOKEN`/`GITHUB_TOKEN`/PAT names); escaped expressions in artifact names or plain inputs are not credential defects and must not fail the check.
- When the automation token cannot push workflow envelopes, the honest split is: runtime hardening plus fail-closed detection in `automation/`, envelope text fixed by separate provisioning, and a tracker test that names the known lines until the envelope lands.
