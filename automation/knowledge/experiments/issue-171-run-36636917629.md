envelope already holds. Source issue #106 was not closed or modified.

## Interpretation

- The execute=failure outcome for run 36635914814 is the executor gate
  working correctly at HEAD, not a lifecycle defect: no worker could
  honestly test what #106 requires, so refusing pre-creation in seconds
  at zero cost is the only honest behavior.
- The reusable defect is consumer-side: the retirement answer now
  exists in four producer forms (eligibility mirror, log verdict,
  structured record key, all proven live) yet every one of them
  requires the consumer to embed registry logic to use it -- which a
  provisioned workflow step cannot do without a checkout-side helper.
  The decision CLI moves the registry consultation into `automation/`
  behind a stable exit-code contract over inputs the finalize step
  already holds (`$RENDER_RESULT_FILE` on the same runner; issue
  text for pre-dispatch shapes), so the provisioned envelope adopts
  the hold with three lines instead of duplicating the registry.
- The adapter is deliberately fail-open toward today's behavior:
  garbage content classifies as not-held (exit 1), so a corrupt input
  can never suppress a legitimate repair; only an explicit registry
  match holds. Embedded hold claims are re-validated, so a stale or
  hand-crafted record can never redirect triage.

## Reusable knowledge

- A signal every producer emits but no consumer can call is not a fix:
  run 36635914814 fired the guard, the log verdict, and the structured
  hold live yet still minted #171. Ship hold decisions as executable
  CLIs over inputs the envelope already holds, with stable exit codes
  provisioned steps can key on without embedding registry logic.
- Keep the registry the single source of truth at the consumer too:
  re-validate embedded hold claims (pair plus successor mapping) so
  stale or hand-crafted records degrade to derived verdicts instead of
  redirecting triage.
- Fail open toward today's behavior at decision boundaries: garbage
  content is not-held (exit 1), never a crash or a suppressed repair;
  only usage errors (missing/unreadable inputs) exit 2.
