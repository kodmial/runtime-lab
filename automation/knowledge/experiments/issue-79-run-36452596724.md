## Interpretation
The missing #77/#78 records mean the issue's stated dependency chain has no durable evidence to build on, so reusing the validated #52/#56/#76 baseline with an explicit substitution note is the honest path rather than blocking or fabricating. The side-effect-import miss confirms why graph-level tests (not permission flags) are the right boundary: top-level static imports are only one spelling of reachability, and the validator now covers `from`, bare, dynamic `import()`, `require()`, and re-export forms. Because the Bun binary cannot be built in this worker, the deliverable that can be completed here is the compile-separation contract (entrypoint + build target + staged exclusion proof + no-rewrite guard + representative-task correctness), with the binary peak delta correctly deferred to a resourced fork builder running the same harness.

## Reusable knowledge
- Coding-only variant contract: lite entrypoint `packages/opencode/src/cli/cmd/run-coding.ts` plus build target `packages/opencode/script/build-lite.ts` (`build:lite`, out `dist/lite`) forms a compile graph separate from full `src/index.ts` / `script/build.ts`; validate by transitive static-import closure, staged per removal group, never by permission flags alone.
- Removal staging that stays reviewable: A (UI/TUI/share/update-catalog, 11 patterns) first, B (MCP/plugins/skills/web-search-fetch/LSP-formatter, 13 patterns) second, C (question/todo/task-subagent/watcher/snapshot-undo, 10 patterns) last with representative-task re-validation; the task-tool check must match path-qualified `agent/task`/`subagent`, never a bare `task` substring.
- Import parsing must cover side-effect `import './x'`, `from`, dynamic `import()`, `require()`, and `export ... from`, or reachability checks silently pass.
- No-rewrite guard: forbid third-party LLM SDK imports and hard-coded provider API hosts outside `provider/` modules plus `provider-direct`/`direct-client` file markers; all model access stays through the existing OpenCode provider/model/session/agent loop.
- Baseline substitution rule: when blocking-issue records are absent from the catalog, proceed only with an explicitly recorded fallback baseline (here issue-52 peak 614,632 kB plus issue-56 anon-mmap) and defer the binary delta to a resourced build with the same harness.
