# Render smoke exposed a controller/runner timeout mismatch

## Hypothesis / objective
Retry issue #9 after fixing workspace parsing and prove create -> deploy -> runner -> cleanup.

## Prior knowledge consulted
The owner-response failure from run 36379129913 and its parser regression test.

## Preconditions / changed premise
Workspace parsing had been fixed to the current `owner.id` contract.

## Procedure
The controller created the service, waited for deploy/health, submitted OpenCode, and polled for a terminal result.

## Observations
- Service creation succeeded.
- Deploy reached `live`.
- Runner health succeeded.
- A runner job was submitted and continued working.
- Controller polling was 60 * 20s = 20 minutes while the runner allows up to 45 minutes.
- The controller declared failure before the runner's valid execution budget expired.
- Mandatory cleanup succeeded and absence was verified.

## Interpretation
The worker was not proven hung; the outer orchestration timeout was inconsistent with the inner job timeout.

## Decision / result
Require the poll envelope to exceed the runner timeout plus margin while remaining inside the workflow envelope.

## Validation
Regression coverage enforces the timeout relationship and the poll budget was increased to about 46m40s.

## Reusable knowledge
Nested timeouts must be monotonic: outer orchestration > inner execution + cleanup/transport margin.

## Unresolved questions / next experiment
Complete a live smoke with the corrected timeout envelope and prove final cleanup.
