## Interpretation

The execute=failure outcome for run 36499977510 is the gate working correctly at HEAD, not a lifecycle defect: storm detection, resubmission, polling envelope, and cleanup never engaged because no worker could honestly test what #110 requires. The reusable defect class -- silent wrong-binary substitution for exact-artifact qualification issues -- stays repaired. The gap this run exposed is diagnostic depth, not refusal logic: the blocker named only the transport gap while the required immutable artifact carries its own proven version defect, so landing delivery without the advisory would trade a seconds-fast refusal for a seconds-fast misclassification. The honest repair is to attach the validated advisory at the single choke point, data-driven so future advisories need no logic changes.

## Reusable knowledge

- Run 36499977510 is the second live post-gate datapoint for #110 and the first at a base containing all prior repairs: the exact-artifact gate refuses the #110-phrased contract pre-creation in seconds with zero Render cost (execute=failure, cleanup=success, no service). Seconds-fast zero-cost refusal remains the expected signature for every future exact-artifact issue until a real delivery mechanism lands.
- Refusal diagnostics for immutable artifacts should carry the artifact's own proven defects, not just the transport gap: artifact `11001896223` is independently blocked by the `0.0.0` version stamp (provider free-tier gate, sub-ceiling peaks, zero pressure events), so its fast-fail can never be read as memory-fit evidence. The advisory map is keyed by immutable (artifact id, source run) pairs and never goes stale.
- Qualify exact workflow artifacts where the credential exists: `automation/opencode_max_headless_qualify.py` downloads, checksum-verifies, and qualifies the artifact under Docker 512m/no-swap in GitHub Actions; Render delivery stays a separate track behind the single `exact_workflow_artifact_blocker` choke point.
