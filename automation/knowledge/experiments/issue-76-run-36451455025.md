## Interpretation
The fork already satisfies the heavy part of the bootstrap (non-empty mirror with upstream history), so the remaining defect was the missing explicit revision record plus a verifiable headless-artifact link. Recording upstream `anomalyco/opencode` base `75e1e7ae...`, tag `v1.18.33` (`1eacc1bd...`), fork `main` `9000e7fc...`, and pin `1.18.33` in `automation/opencode-fork.baseline.json` closes that gap without touching the fork. Version equality across fork manifest, runner pin, installer pin, and release asset means the default branch builds the same headless CLI artifact we benchmark; the Contents-API file presence (entry, run command, build script, lockfile) is sufficient build-readiness proof given a full Bun build is impractical in this worker. The existing `kodmial/opencode#1` note plus the baseline ownership block enforces the ownership rule with no new fork backlog. Preserved SHAs plus the documented fetch/rebase steps keep the fork syncable.

## Decision / result
Keep `kodmial/opencode` as the source-only fork with `kodmial/runtime-lab` as the sole tracking owner: baseline file `automation/opencode-fork.baseline.json`, helper `automation/opencode_fork.py`, tests `automation/test_opencode_fork.py`, and the promoted topic-note entry are the bootstrap deliverables. No fork content, issue, or workflow changes were made by this run.
