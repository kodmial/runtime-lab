## Interpretation

The execute=failure outcome for run 36503746345 is the gate working correctly at HEAD, not a lifecycle defect: storm detection, resubmission, polling envelope, and cleanup never engaged because no worker could honestly test what #110 requires. The reusable defect class -- silent wrong-binary substitution for exact-artifact qualification issues -- stays repaired. The gap this run exposed is retirement signaling, not refusal logic: a log-only permanent block without a successor pointer forces every redispatch through an identical text-scraping repair investigation even though the project already retired this contract (owner direction plus coordinator `SUPERSEDED_ARTIFACT_IDS`). The honest repair is to attach the validated superseded redirect at the single choke point, data-driven so future retirements need no logic changes, while keeping the zero-cost pre-creation refusal unchanged.
