# Hold retired exact-artifact smoke bodies at dispatch instead of minting repairs (repair run 36629441608)

## Hypothesis / objective

Run 36629441608 (source issue #106, smoke) failed in `render-job.sh` at the
exact-artifact pre-creation gate with `infrastructure-blocked` for the retired
artifact `11001896223` (workflow run `36492639568`) plus the known-artifact

## Preconditions / changed premise

Material premise vs all prior #106 repairs (#115 gate, #118 delivery
verification): the executor gate, the superseded redirect, and the
structured `permanent` refusal record are all correct at this checkout and
reproduce the live refusal byte-for-byte, yet #106 redispatched anyway and
minted repair #154. The changed premise is the failure location: the defect
is no longer in the executor (which refuses correctly in seconds at zero
cost) but in dispatch -- a smoke issue carries no `qualification:render`
label, so the finalize path emits `classification=not-chain` with an empty
fingerprint and the fingerprint-dedup branch never fires. Per protocol this
repair does not repeat the live Render experiment; it fixes that reusable
dispatch gap. Source issue #106 was not closed or modified. This run
creates no Render service (no executor envelope here by design).

## Interpretation

- The execute=failure outcome for run 36629441608 is the executor gate
  working correctly at HEAD, not a lifecycle defect: no worker could
  honestly test what #106 requires, so refusing pre-creation in seconds
  at zero cost is the only honest behavior.
- The reusable defect is dispatch-side: the retirement signal exists in
  the refusal record (`permanent`/`superseded`/`successor` per #125/#133)
  and in the durable qualification payload (per #138), but smoke issues
  never reach the classifier, so the finalize envelope cannot dedup them
  and the scheduler keeps redispatching the retired body. The guard moves
  this class from per-redispatch refusal-plus-repair to pre-dispatch
  ineligibility with the same stable successor redirect.
- The guard is deliberately data-driven and narrow: only bodies carrying
  a `SUPERSEDED_WORKFLOW_ARTIFACTS` exact-artifact conjunction guard;
  ordinary smoke and supported-contract (successor/PR #15) bodies flow
  through unchanged, and paused/unprioritized semantics keep precedence.

## Reusable knowledge

- A correct fail-closed executor refusal can still loop forever when the
  dedup signal lives on a path the failing issue never reaches: smoke
  issues skip the qualification classifier, so fingerprint dedup never
  fires for them. Retirement must be checked pre-dispatch from the issue
  body, not only post-failure from the result file.
- Pre-dispatch guards for retired contracts must be data-driven off the
  same `SUPERSEDED_WORKFLOW_ARTIFACTS` registry as the executor redirect
  (single source of truth for "retired"), pure/never-raising, and placed
  after priority/paused semantics so existing scheduling behavior is
  preserved for every non-retired issue.
- To retire a future artifact, add one entry to
  `SUPERSEDED_WORKFLOW_ARTIFACTS`; guard, notice, blocker, refusal
  record, and eligibility redirect all follow without logic changes.
