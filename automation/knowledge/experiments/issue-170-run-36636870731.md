# Repair stale profile-env config that would reintroduce the #58 ceiling storm

## Hypothesis / objective

Repair the concrete reusable defect behind the Render execution failure for source issue #58 in run 36635571284 (execute=failure, cleanup=success, smoke mode): the run storm-aborted with 4 proven worker restarts while pinned at the 512 MB cgroup ceiling at base `c176ad7`, which already contains the full production low-memory profile (issues #75/#159/#164). The storm breaker fired exactly as designed, so the harness is not the defect; the remaining defect in this failure mode is the stale qualification helper `opencode_lowmem_profile.lowmem_env()`, which still emitted a permission-only `OPENCODE_CONFIG_CONTENT` while production carries the full 8-key `lowmem_config()`. Any worker provisioned from profile files (`write_profile_files` -> `opencode.env`) would therefore reintroduce the exact run-36632841000 gap. Success evidence: `lowmem_env()` emits the full config, `validate_profile` rejects permission-only documents, production/qualification parity is regression-locked, and the offline suites pass.

## Interpretation

- The storm breaker converts a systematic capacity mismatch from a 45-minute budget burn into a ~12-minute fail-fast with an actionable diagnostic, but it cannot make an oversized workload fit. With production fully wired, the reusable repair is to eliminate the remaining vector that would silently unwire it: the qualification helper is the source of truth for profile-file provisioning and for the #81 gate's fingerprint, so its stale document would reintroduce the storm on any consumer while passing validation.
- The strengthened `validate_profile` now describes production truthfully: the embedded config must equal the full qualified document, and every `STATIC_ENV` kill-switch (including the embedded-web-UI flag) is required. This keeps the qualification gate and any future profile-file worker provisioning storm-free by construction.
- As in prior repairs, the remaining ~88 MiB gap between the ~600 MB agent peak and the 512 MB limit is not claimed closed by config wiring; live re-dispatch of #58 must confirm the storm no longer fires, and any smaller-binary track (coding-only/direct-headless) stays with the qualification chain.
