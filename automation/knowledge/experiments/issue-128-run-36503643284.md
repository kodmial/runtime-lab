# Exact OpenCode artifact delivery and /proc identity for Render

## Interpretation

- The issue-#115 substitution defect is now closed for the supported contract without reopening it for anything else: the gate is still the single choke point, but it distinguishes the deliverable artifact from genuinely undeliverable ones instead of refusing everything.
- Keeping GitHub credentials controller-side only (push bytes, never tokens) is what makes the transport compatible with the issue-#39 scrubbed-child invariant by construction rather than by audit.
- Absolute-path launch plus `/proc/<pid>/exe` comparison is the only proof that answers "which binary actually executed" rather than "which file was staged"; the script-vs-ELF test finding is why the harness must never treat a staged-file checksum as execution proof.
- Evidence riding the terminal result (rather than worker disk) is what survives the documented anytime-restart/OOM replacement; no new persistence mechanism was needed because the result file already lives controller-side.

## Reusable knowledge

- Exact workflow artifacts are deliverable to ephemeral Render workers without ever giving the worker a GitHub credential: controller-side authenticated fetch, full checksum verification before use, and a bytes-only push to a worker transport endpoint that re-verifies before staging.
- `/proc/<pid>/exe` (realpath + SHA read from the executing file, plus cmdline/parent) is the execution-identity proof; staged-file checksums alone cannot prove which binary ran, and script binaries intentionally resolve to their interpreter.
- A fail-closed gate can grow a supported path without weakening: keep one decision function, require the full conjunction (id + run + archive digest + binary digest + version), and refuse everything else with the original diagnostic.
