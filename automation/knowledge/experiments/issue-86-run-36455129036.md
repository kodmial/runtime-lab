# Build and fingerprint OpenCode experiment artifacts in parallel

## Hypothesis / objective

A shared, stdlib-only pipeline can build deterministic standalone Linux
OpenCode binaries from arbitrary explicit `kodmial/opencode` experiment
refs and let Runtime Lab/Render consume exactly those artifacts: explicit
ref in, immutable runnable Linux artifact out, selectable per worker,
with several hypotheses built and tested independently and concurrently
while the upstream pinned binary remains a non-fallback baseline.

## Interpretation

The pipeline meets the issue body point by point without live builds:
explicit refs replace `latest`; the Bun compile/release path is the
shared build shape; Linux x86-64 is the required fingerprinted arch;
manifests record all five fingerprint fields plus build identity and an
immutable GitHub-backed URL; provisioning selects the exact binary;
readiness fails on mismatch; ids are content-addressed so hypotheses
run concurrently; the baseline never serves as a fallback in experiment
mode. What remains genuinely live (resourced `bun` build of each fork
branch, release upload, Render memory trials) is workflow-owned and
explicitly out of scope for this offline run.

## Decision / result

Land the shared infrastructure: `automation/opencode_artifact.py`,
`automation/build-opencode-artifact.sh`,
`automation/install-opencode-artifact.sh`, runner/lifecycle wiring in
`automation/opencode_runner.py`, `automation/runner_server.py`,

`automation/test_opencode_artifact.py` and the topic-note section. Any
memory experiment can now hand the builder a commit/ref and Render can
select the exact artifact before a memory test; multiple hypotheses
build and test independently and concurrently.

## Reusable knowledge

- Content-address artifact storage by resolved fork SHA
  (`.opencode-artifacts/exp-<12>/`), never by branch name: mutable
  names collide under concurrency, SHAs do not.
- Experiment readiness is fingerprint equality (manifest fork SHA +
  binary SHA-256 + executability + `--version` probe), not version
  string equality: fork builds keep the same `1.18.33` version while
  differing in bytes.
- Keep installer mentions out of experiment-mode scripts even in
  comments when the contract says "no installer fallback": literal
  strings become false-positive surface for grep-based guards.
- Render selection travels in both commands: the build command must
  provision the artifact (build-time) and the start command must pin
  the fingerprint (run-time), or a rebuilt worker silently drifts.
