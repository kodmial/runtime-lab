# Benchmark a direct headless OpenCode path in parallel

## Hypothesis / objective

Bypassing unnecessary internal HTTP/server/SDK plumbing in the headless
OpenCode path materially reduces memory while preserving the existing
session/agent/provider/tool implementation. This run builds the
reproducible direct-headless variant contract in isolation (own files, own
branch plan, no coupling to #78/#80/#86/#81 outcomes), benchmarks it
against the normal headless path with the same workload and telemetry as
the other memory experiments, and records the memory and correctness
deltas.

## Reusable knowledge

- Direct-path shape that bypasses routing without touching semantics: a
  separate `run-direct` entry calling session/agent/provider/tool
  functions directly (no `app.fetch()` hop), a pruned `server-direct`
  route surface, and a minimal `bootstrap-direct` — never a flag on the
  full path and never a custom provider client.
- Step-0 honesty rule applied: when config flags show no startup/RSS
  movement at the `--version` level, record the null result and point at
  the binary build as the only remaining lever instead of claiming a win.
- Reuse rule: benchmark new memory tracks with the exact #81 field list
  (imported, not copied) and the shared FOO_LIMIT workload so rows stay
  1:1 comparable across parallel tracks.
- Runner selection rule: gate direct-binary use on an existing
  executable override with fail-closed fallback to the normal path, so
  the experiment is always runnable and revertible.
