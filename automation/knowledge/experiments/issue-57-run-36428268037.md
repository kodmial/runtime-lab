# Port kodmai cgroup memory telemetry into the Render worker

## Hypothesis / objective

Port the proven container-level cgroup measurement approach from the private
`kodmial/kodmai` project into the runtime-lab Render worker so a live Render
memory experiment can observe the actual Render cgroup memory consumed by the
whole worker (including the OpenCode child process), instead of only the
Python runner's own RSS. Success evidence: cgroup files (not Render's metrics
API) drive the measurements, `GET /health` carries them, GitHub Actions
retains telemetry across worker restarts, process-level diagnostics stay
available separately, and the offline suite passes.

## Preconditions / changed premise

New P0 instrumentation with no prior cgroup telemetry in the worker; not a
repeat of any failed experiment. Fully offline implementation (no live Render
credentials or service used); the live memory experiment itself is the
dependent issue and runs later.

## Procedure

1. Added `automation/cgroup_memory.py` (stdlib-only): resolve the process
   cgroup from `/proc/self/cgroup` (v2 `0::/path` preferred, v1 memory
   controller fallback, mount-root fallback), then read v2
   (`memory.max`/`memory.current`/`memory.peak`/`memory.swap.current`/
   `memory.swap.max`/`memory.events`/`cpu.max`/`cpu.stat`) with v1 fallback
   (`memory.limit_in_bytes`/`memory.usage_in_bytes`/`memory.max_usage_in_bytes`/
   memsw files/`memory.oom_control` oom_kill/cpuacct). Unlimited markers
   (`max`, near-2^63 values) normalize to None; every file read fails
   independently so a missing source degrades only its own fields.
2. Extended `automation/runner_server.py::read_resource_diagnostics` with a
   `cgroup` snapshot beside the unchanged RSS/HWM fields; `health_snapshot`
   (and therefore `GET /health`) carries it with no new dependencies.
3. Added `automation/render_memory_sampler.py` (stdlib-only, runs on the
   Actions side): ~1s interval (clamped to 2s max), self-bounding max
   duration, transport failures stored as gap samples, JSONL log on the
   Actions side, plus `summarize_samples`/`render_human_summary` (limit, max
   current/peak, max RSS, instance change, event-counter deltas, swap,
   sample counts, restart/harness-event timestamps).
4. Updated `automation/render-job.sh` only (no `.github/workflows/**`
   changes): after healthy / before submit, start the sampler in the
   background; record `job_resubmitted`/`fallback_submitted` event markers
   with timestamps; an EXIT trap stops the sampler (bounded graceful wait,
   then SIGKILL), prints the human summary, writes the JSON summary file,
   and best-effort merges it into the collected job result as
   `memory_telemetry` (extra keys are ignored by the result parser).
5. Added `automation/test_cgroup_memory.py` (19 tests): v2 512 MB normal
   case, v2 root fallback, v1 fallback, unlimited markers, missing/unreadable
   degradation, events parsing, peak/swap unavailable, health exposure,
   sampler restart survival with pre-restart retention, bounded cleanup, and
   harness static invariants (start order, interval bound, trap cleanup,
   no secrets).

## Interpretation

- The worker can now report total container memory (cgroup files) while an
  OpenCode child runs, distinct from the Python RSS -- the exact signal the
  live experiment needs to discriminate OOM/resource restarts (open question
  from the issue #53 record) from host maintenance.
- Keeping the observer (sampler + samples + summary) on the Actions side is
  what makes the telemetry survive the anytime-restart contract that wipes
  in-process worker state.
- Merging `memory_telemetry` into the job result as an additive key preserves
  the existing result contract while placing the evidence where the
  experiment record can cite it.

## Reusable knowledge

- Resolve the worker cgroup from `/proc/self/cgroup` (v2 entry first, v1
  memory entry second, mount root last) and read container memory from
  cgroup files, never from host RAM or parent RSS alone.
- Treat `max` and near-2^63 limits as unlimited (None), not as real byte
  counts, and degrade per missing file rather than failing the snapshot.
- Sample constrained workers from outside the container at ~1s into
  Actions-side JSONL so restarts cannot erase pre-restart evidence; record
  poll gaps explicitly instead of dropping them.

## Unresolved questions / next experiment
