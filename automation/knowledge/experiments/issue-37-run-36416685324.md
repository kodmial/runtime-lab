# Knowledge-store settings correction: enable Issues on the private ledger

## Hypothesis / objective
The private `kodmial/agent-knowledge` ledger was bootstrapped with GitHub Issues disabled (`has_issues=false`), which blocks the Knowledge Plane roadmap from living in its own repository as native issue dependencies. The correction (PATCH `has_issues=true`, bootstrap default fix, regression coverage) can be applied through the already configured trusted credential path with the repository remaining private and all prior bootstrap guarantees intact.

## Preconditions / changed premise
Material premise changed versus run 36413374778: the live private repository now exists (created by that run) but was observed with `has_issues=false`, which the Knowledge Plane roadmap requires to be `true`. This run does not repeat the repository-creation experiment; it executes the repository-settings correction the issue requires. `TAP_PAT` arrives as `GH_TOKEN`/`GITHUB_TOKEN` (literal `TAP_PAT` absent); availability is decided by live authenticated capability, never by token format/value, and no token value was printed, persisted, or committed.

## Interpretation
The correction is minimal and safe: exactly one boolean (`has_issues`) changed on the live repository; visibility and all other security settings are untouched both in the PATCH body and in the bootstrap default. The bootstrap default fix plus `require_private_bootstrap_request` enforcement guarantees future recreation cannot silently re-disable Issues, and the new regression tests lock that contract offline. The trust boundary, CAS/bounded-retry, immutability, explicit topic-merge, and scoped App-token-path semantics are unchanged. Migration remains #34-compatible (9/9, byte-preserving) with public copies intentionally left in place per the issue.

## Decision / result
Keep `private agent-knowledge repo -> trusted layer (PAT-as-GH_TOKEN now, App installation token target) -> credential-free worker context -> validated CAS persist` with the canonical #34 record model, `POST /user/repos` as the only bootstrap endpoint, and GitHub Issues enabled (`has_issues=true`) on the knowledge repository for the Knowledge Plane roadmap. The settings-correction conclusion of this run supersedes the `has_issues=false` bootstrap premise of run 36413374778; all other conclusions of that run (endpoint, transport, privacy, migration) are reaffirmed, not replaced.
