## Observations

- The failed run behaved exactly as designed by the issue #68/#71 repairs up to the terminal error except for the breaker verdict: correct fail-fast classification (3 consecutive 404s per loss), correct health qualification (healthy at every proven loss), correct restart proof (instance rotation on all ten losses), correct ten resubmissions. Classification, detection, and diagnostics are not the defect; the gap-blind pressure evidence is.
- The eleven job lifetimes (~44 minutes wall-clock including deploy/health) exactly fill the unchanged 140x20s (46m40s) poll budget: the budget was sized for ONE 45-minute execution, so every resubmission shrinks the next attempt's window below the runner's 45-minute timeout (shared-budget starvation, same shape as run 36439192645).
- The existing storm shell test pre-seeds a contiguous pressure file, so the background sampler's appended trailing gaps never break the pre-seeded transitions and the test passes despite the bug; no existing test interleaves gaps/events between instance groups as live does.
- After the fix, the same interleaved shape reports pinned usage with 2+ transitions and abandons; a gap inside one instance lifetime no longer splits its stall surge.

## Interpretation

The storm breaker had the right gate (streak plus live pressure) but the wrong continuity rule: restart down-windows are observable as telemetry gaps plus harness event markers, and those entries must be skipped without breaking replacement/surge continuity. Resetting on gaps converts every live storm into "zero transitions, split surges" and fails open toward resubmission forever -- the breaker can never fire live. The reusable fix is gap-tolerant evidence (ignore gaps/events for continuity, reset only on instance change), matching the summary path that already preserves previous across gaps. Transient clusters without pinning still keep full budget-limited recovery, and genuine telemetry gaps (no usable samples) still fail open.

## Decision / result

- `automation/render_memory_sampler.py`: `memory_pressure_evidence()` no longer resets `previous` or the stall group on gap samples (ok=false), event markers, or samples without numeric cgroup fields; those entries are skipped with continuity preserved and groups reset only on instance change. Transition counting now matches `summarize_samples()`. Docstring updated to the gap-tolerant discipline with run 36442675039 cited.
- `automation/test_cgroup_memory.py`: new `test_memory_pressure_counts_transitions_across_gaps_and_events` (live-shaped interleaved gaps plus `job_resubmitted` events still report pinned replacements and pressure, including through the file helper) and `test_memory_pressure_surge_survives_gaps_within_instance` (a gap inside one instance lifetime preserves the stall surge).

## Reusable knowledge

- Storm pressure evidence must be gap-tolerant: sampler gaps (ok=false during restart down-windows) and harness event markers separate every live replacement, so resetting continuity on them reports zero transitions live. Skip those entries with continuity preserved; reset stall groups only on instance change, matching the summary path.
- Shell/HTTP storm fakes that pre-seed contiguous pressure files do not reproduce live: regression coverage must interleave gaps and event markers between instance groups.
- Shared-budget starvation applies to any resubmission chain (storm or not): the 140x20s envelope covers ONE 45-minute execution, so each resubmission shrinks the next attempt's window.
