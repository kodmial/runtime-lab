# Repair missing low-memory defaults that thrashed run 36449610030 at the 512 MB ceiling

## Hypothesis / objective

Repair the concrete repository defect behind the Render execution failure for source issue #58 in run 36449610030 (execute=failure, cleanup=success, smoke mode): the production OpenCode workload ran without the validated low-memory defaults, so its peak sat higher than the best measured configuration while every child stream was also buffered fully in Python RAM. Success evidence: the reusable runner applies `BUN_OPTIONS=--smol` and disk-backed output spooling by default, regression tests pin both behaviors, and the offline suite passes.

Material premise changed since the issue #73 repair: run 36449610030 is the first live run to exercise the gap-tolerant storm breaker (base commit 1f310c1, the issue #73 repair itself) and the breaker fired exactly as designed — initial job plus 3 resubmissions, then fail-fast on the 4th proven restart with memory pressure instead of burning the 140-poll budget. ## Procedure

1. Inspected run 36449610030 via `gh run view 36449610030 --repo kodmial/runtime-lab --log`: service `srv-dat95dh7lnhs73c58910` created (plan=free, region=oregon), deploy `dep-dat95e17lnhs73c58ac0` live, runner healthy, job `c5f4292f00b2401eab0133e78f8f6981` submitted 16:16:54, lost to 4 proven restarts and resubmitted 3 times (`0703a1fe` / `44cde9ba` / `3673e0b3` at ~2-3 minute intervals, instances 665689915be4 -> 7f19f7c37b34 -> 4198e9348ef3 -> 6c8259d23e7e -> 807ca1247bec), then fail-fast storm diagnostic on job `3673e0b3defc4f9087a95486fd01403c` at 16:27:47; cleanup verified deletion (HTTP 404).
2. Read the run's memory summary: cgroup limit 512.0 MB, current max 512.0 MB, peak 512.5 MB, Python RSS ~31 MB, swap 0, memory.events deltas all 0, 5 instance ids with 4 restart transitions — the worker was pinned at the ceiling while the agent ran, matching the systematic ~600 MB vs 512 MB mismatch.
3. Re-verified the platform contract against current official vendor documentation (`https://render.com/docs/free`, fetched 2026-09-28): Free web services are 0.1 CPU / 512 MB, "Render might restart a Free web service at any time", ephemeral filesystem lost on restart/redeploy/spin-down, single instance, no persistent disks. No material contract change.
4. Traced the workload gap: `default_opencode_env_overrides()` in `automation/opencode_runner.py` carried only confinement settings and was never called by production (`JobManager.__init__` set only `OPENCODE_CONFIG_CONTENT`/`GIT_TERMINAL_PROMPT` directly), so `BUN_OPTIONS=--smol` — the issue #56 "harmless default" — never reached the worker; `SubprocessCommandRunner.run` used unbounded `subprocess.run(..., stdout=PIPE, stderr=PIPE)`, buffering every child stream fully in Python RAM plus decoded/combined copies.
5. Wired the defaults in (`BUN_OPTIONS=--smol` via the single canonical overrides helper, disk-backed spooling with a 512 KiB per-stream read-back cap in the command runner), added regression tests, and ran the offline suite.

## Observations

- The failed run behaved exactly as designed by the #71/#73 repairs up to the terminal error: correct fail-fast classification (3 consecutive 404s per loss), correct health qualification (healthy at every proven loss), correct restart proof (instance rotation on all 4 losses), correct 3 resubmissions, correct storm abandonment with pressure evidence (pinned at limit plus 4 transitions). The harness is not the defect; the missing low-memory wiring is.
- `BUN_OPTIONS=--smol` appears only in `automation/disk_heap_benchmark.py` mode envs and benchmark artifacts ("minor help only ... Keep as a harmless default, not a fix"); no production path set it. `default_opencode_env_overrides()` was dead code (defined, zero callers), so the canonical-defaults seam had already drifted from what production applied.
- The old `SubprocessCommandRunner` held each child stream twice over (PIPE bytes plus decoded `str` plus the runner's combined `last_output` copy) with no bound; on a 45-minute agent run any chatty child grows Python RSS without limit on a box with ~0 MB headroom.
- After the fix, small outputs keep full fidelity (cap far above the 4000-8000 char result limits) while pathological outputs are capped at 512 KiB per stream; timeout (124), missing-binary (127), and non-zero-exit semantics are unchanged.

## Interpretation

The storm breaker converts a systematic capacity mismatch from a 45-minute budget burn into a ~12-minute fail-fast with an actionable diagnostic, but it cannot make an oversized workload fit. The reusable repair is to actually run the best validated configuration: every saved megabyte and every bounded buffer counts when the agent peak rides the ceiling. `BUN_OPTIONS=--smol` (~40 MB) plus bounded spooling does not by itself prove 512 MB reliable — issues #52/#56 already measured that no software default does — but shipping the storm without the validated defaults guarantees the worst-case peak on every attempt. Wiring them as non-clobbering defaults keeps operator overrides intact while making the production path match the measured best case.

## Decision / result

- `automation/opencode_runner.py`: new `OPENCODE_LOW_MEMORY_BUN_OPTIONS = "--smol"` / `OPENCODE_LOW_MEMORY_ENV_VAR = "BUN_OPTIONS"` constants; `default_opencode_env_overrides()` now includes `BUN_OPTIONS=--smol` (with the #56/run-36449610030 rationale); new `apply_opencode_env_overrides()` setdefault helper that never clobbers explicit operator values.
- `automation/runner_server.py`: new `_SPOOL_READ_CAP_BYTES = 512 KiB` plus `_read_spool_prefix()`; `SubprocessCommandRunner.run` reworked from unbounded `subprocess.run(PIPE)` to `Popen` with unlinked `TemporaryFile` spools and capped read-back (timeout->124 with kill, missing/unrunnable->127, same `CommandResult` shape); child env always gains the canonical overrides without clobbering; `JobManager.__init__` applies the canonical overrides via setdefault loop (single source of truth, fallback to the two legacy setdefaults).
- `automation/test_opencode_runner.py`: new low-memory override tests (smol present, no-clobber, non-mapping rejection).
- `automation/test_runner_server.py`: new spool-runner tests (stdout/stderr capture, non-zero exit, missing-binary 127, timeout kill/mark, pathological-output cap, child-env smol default without clobbering operator value, manager-init setdefault without clobber).
- `automation/knowledge/topics/render-lifecycle.md`: promoted the low-memory-default rule with this record as evidence; preserved prior history.

## Reusable knowledge

- The canonical OpenCode subprocess defaults live in `opencode_runner.default_opencode_env_overrides()` and must be applied (not duplicated) by the runner: `BUN_OPTIONS=--smol` is a validated harmless default (~40 MB off peak), and explicit operator values always win via setdefault semantics.
- Child-process capture on a 512 MB worker must be disk-backed with a read-back cap, never unbounded PIPE: spool to unlinked temp files, read at most a fixed prefix (512 KiB per stream here), keep timeout/missing-binary/exit semantics identical.
- A correctly firing storm breaker does not exonerate the workload: when the breaker fires as designed, the next repair looks at what peak the workload carried into the storm, not at the breaker.

## Unresolved questions / next experiment
