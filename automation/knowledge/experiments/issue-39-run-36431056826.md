## Interpretation
The #37 core (personal-account endpoint, private enforcement, Issues-enabled correction, canonical migration, CAS/bounded-retry, redaction, worker-payload scan) reproduces live and remains sound. The genuine gaps were all above the unit-test line: silent listing, retry-loop TOCTOU windows, mocks-only persistence, unwired task enrichment, and process-env leakage around an otherwise clean payload boundary. Each fix is narrow, backward compatible (optional enrichment parameter, scrub-only removal of six credential names, fail-closed instead of silent-empty), and locked by a regression test that fails on the old code. The live store needs a follow-up migration of the 10 newer local records, but that is record administration, not a code defect, and was deliberately left untouched to avoid modifying history inside a review task.

## Decision / result
Keep `private agent-knowledge repo -> trusted layer (PAT-as-GH_TOKEN now, App installation token target) -> credential-free worker context plus scrubbed worker env -> validated CAS persist` with the canonical #34 record model and `POST /user/repos` as the only bootstrap endpoint. The review repairs land in `automation/knowledge_store.py` (scrub helpers, shared merge, fail-closed listing, retry-loop re-checks, `GitHubApiKnowledgeBackend`, `render_trusted_task_text`), `automation/opencode_runner.py` (scrub helpers), `automation/runner_server.py` (scrubbed child env), and `automation/render_controller.py` (optional `knowledge_context` enrichment), covered by 8 new tests. The Actions workflow is intentionally unmodified; the env-leak fix lives in the automation layer that owns subprocess construction.

## Reusable knowledge
- Retry-loop invariant: every CAS `refresh_fn` must re-check its guard (immutability, expected version) on each attempt, never only before the loop; the regression tests interleave a winner at CAS time to prove it.
- Backend listing must fail closed: a store that cannot enumerate its namespace must raise, never return a silent empty list that masquerades as "no knowledge".
- Production knowledge reads/writes go through `GitHubApiKnowledgeBackend` (injected `api` callable, Contents reads, Git-database CAS writes with `force=false`); `DictGitHubBackend` stays tests-only.
- Worker trust has two halves: the payload (`build_worker_context` plus `render_trusted_task_text`, both scanned) and the process env (scrub the six storage-credential names for every worker child process). Either half alone is insufficient on Actions, where step env is inherited.
- Controller enrichment is opt-in per dispatch (`knowledge_context=None` preserves the baseline); oversized contexts fail closed instead of truncating.
