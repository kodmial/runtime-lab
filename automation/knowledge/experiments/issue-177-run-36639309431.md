# Specify the finalize mint-vs-hold branch for retired contracts (repair run 36638450066)

artifact `11001896223` (workflow run `36492639568`) plus the known-artifact

## Interpretation

- The execute=failure outcome for run 36638450066 is the executor gate
  working correctly at HEAD, not a lifecycle defect: no worker could
  honestly test what #106 requires, so refusing pre-creation in seconds
  at zero cost is the only honest behavior.
- The reusable defect is branch-specification, not signal-side: the
  retirement answer now exists in five producer forms (eligibility
  mirror, log verdict, structured record key, hold CLI, all proven live)
  yet none of them tells the consumer which finalize branch wins nor
  which successor text to post. The finalize-gate helper moves that
  branch logic into `automation/` behind a pure, tested contract over
  inputs the finalize step already holds (hold decision, repair count,
  budget, open-repair marker, source/failed-run ids), so the provisioned
  envelope adopts the hold by branching on the returned action and
  posting the returned notice while keeping the source paused.
- The gate is deliberately fail-open toward today's behavior: garbage
  content classifies as mint/duplicate/exhausted by the count inputs,
  never as a suppressed repair; only an explicit registry-backed hold
  (artifact/run pair in `SUPERSEDED_WORKFLOW_ARTIFACTS`) returns hold.

## Reusable knowledge

- Answering held/not-held is not a fix when the consumer still has to
  invent the branch: run 36638450066 answered held live yet still minted
  #177. Ship the consumer branch with the signal -- mirror the
  envelope's mint/duplicate/exhausted cases with the hold inserted
  first, plus the exact notice text, over inputs the envelope already
  holds.
- Keep suppression narrow and fail open: only a registry-backed hold
  skips minting; garbage content follows the count inputs toward
  today's behavior so a corrupt input can never suppress a legitimate
  repair.
- Keep the registry the single source of truth at the consumer too:
  re-validate the held pair against `SUPERSEDED_WORKFLOW_ARTIFACTS`
  before returning hold, so stale or hand-crafted decisions degrade to
  mint/duplicate/exhausted instead of redirecting triage.
