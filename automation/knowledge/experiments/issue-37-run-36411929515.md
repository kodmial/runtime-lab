# Built private long-term agent knowledge store abstraction with offline proof

## Hypothesis / objective
A centralized private knowledge ledger at `kodmial/agent-knowledge` can be integrated via a tested storage abstraction that reuses the canonical issue #34 record model, enforces the ephemeral-worker trust boundary, uses optimistic CAS writes without full clones, and pauses only the live bootstrap when `TAP_PAT` is unavailable.

## Prior knowledge consulted
- `automation/knowledge/PROTOCOL.md` (READ -> PLAN -> EXECUTE -> RECORD -> PROMOTE; unique per-run files; records immutable).
- `automation/knowledge/topics/agent-execution.md` (durable memory boundary; catalog-first discovery; strict JSON front matter; no workflow edits).
- `automation/knowledge/topics/render-lifecycle.md`, `scheduler-recovery.md` (ephemeral worker naming; one worker per attempt; repair with regression coverage).
- `automation/knowledge/decisions/ADR-0001-repository-agent-memory.md` (Git handoff boundary; per-run files avoid conflicts).
- `automation/knowledge/experiments/issue-34-run-36410184254.md` (canonical strict-JSON schema, deterministic catalog, no committed index).
- `automation/knowledge/experiments/issue-9-run-36379129913.md`, `issue-31-run-36408413138.md`, `issue-33-run-36409578168.md` (API-shape helpers with tests; classify polls from HTTP status; bounded same-worker recovery).
- `automation/knowledge/experiments/issue-27-run-36405661952.md`, `issue-28-run-36405666089.md` (fail-closed ownership; offline fault matrix).
- `automation/knowledge_catalog.py` and `automation/github_app.py` (canonical validation/query semantics; short-lived installation tokens with refresh/redaction).

## Preconditions / changed premise
No private knowledge repository or storage adapter existed; issue #34 had already landed the canonical schema/catalog, so this run reuses that model directly instead of inventing a second format. `TAP_PAT` was verified absent in this environment (`TAP_PAT available: False`), so the live-bootstrap portion is a new paused-blocker premise, not a repeat of any prior experiment. Fully offline except the credential-availability probe, which read only the variable name presence and never the value.

## Procedure
1. Queried the catalog and read the protocol, all topic notes, the ADR, and prior experiment records before changing code.
2. Added `automation/knowledge_store.py` (stdlib only): private-bootstrap request builder requiring `private=true`, repository verifier rejecting public reuse, `TAP_PAT` status/blocker helpers with explicit safe message and no public fallback, project-namespace path helpers (`projects/<project>/experiments|topics|decisions`, root `schema/`), credential-free worker context builder with fail-closed scan, canonical #34 migration/identity verifiers, `KnowledgeStore` adapter with `InMemoryKnowledgeStore` and CAS-backed `GitHubKnowledgeStore` (`DictGitHubBackend` fake, `cas_commit_files_with_retry` bounded by `MAX_CAS_ATTEMPTS`), scoped GitHub App token request/provider reusing `github_app.InstallationTokenProvider` refresh/redaction, and credential-free live-bootstrap planner.
3. Added `automation/test_knowledge_store.py` (21 offline tests) covering every required behavior: private bootstrap, public rejection, PAT redaction, worker trust boundary, project namespaces, immutability, CAS retry/bounds, topic merge without loss, App scoping to a repo other than source, `TAP_PAT` blocker, and migration identity preservation including all 7 existing public records.
4. Ran the full offline suite and catalog validation; promoted reusable facts to `automation/knowledge/topics/agent-execution.md`.

## Observations
- `TAP_PAT` probe returned unavailable; `plan_live_bootstrap` raises `KnowledgeAuthBlocker` with the documented manual-setup message and never proposes a public fallback.
- Full suite: 293 passed (272 pre-existing plus 21 new) with no network, credentials, or service.
- `python3 automation/knowledge_catalog.py validate` reports ok; deterministic catalog build confirmed.
- Every existing public record migrates cleanly through `migrate_experiment_text` with identity/provenance verified.
- `git status --short` shows only the two new source files, the updated topic note, and this record; no `.github/workflows/**` changes.

## Interpretation
The format-independent storage/auth abstraction plus the verified #34-compatible migration path satisfies the issue without a second record model. The trust boundary holds by construction: worker contexts are scanned and contain knowledge only, while PAT/App tokens stay in the trusted layer. CAS with bounded retries preserves independent experiment records and forces explicit topic merges. The only unproven portion is the live GitHub bootstrap, which is correctly paused behind the credential blocker.

## Decision / result
Keep `private agent-knowledge repo -> trusted layer (App/PAT) -> credential-free worker context -> validated CAS persist` with the canonical #34 record model. Normal access uses short-lived installation tokens scoped to `kodmial/agent-knowledge` (`metadata:read` + `contents:write`); no full clone in normal execution; fail closed on public repo, unauthenticated target, insufficient permissions, unproven writes, schema failure, immutable overwrite, or exhausted CAS budget.

## Reusable knowledge
- Worker payloads must be built by the trusted layer from selected knowledge and scanned for credential markers and token shapes before handoff; any hit fails closed.
- Private-repo bootstrap requests must assert `private=true` at build time and re-verify `full_name`, `private`, visibility, and default branch at read time; never silently reuse a public repo.
- `TAP_PAT` needs explicit redaction coverage beyond generic `*TOKEN*` scans because the name lacks the `TOKEN` marker.
- Immutable experiment paths plus CAS commit/update with a bounded budget preserve concurrent records; topic notes require expected-version checks and explicit line-union merge, never silent overwrite.
