## Interpretation

The execute=failure outcome for run 36500759174 is the gate working correctly at HEAD, not a lifecycle defect: storm detection, resubmission, polling envelope, and cleanup never engaged because no worker could honestly test what #110 requires. The reusable defect class -- silent wrong-binary substitution for exact-artifact qualification issues -- stays repaired. The gap this run exposed is evidence depth, not refusal logic: a log-only refusal forces every redispatch through an identical text-scraping repair investigation, and a future scheduler cannot skip a known-permanent block without a stable signal. The honest repair is to leave a stable structured record on the gate path -- distinct from runner job results so no poll consumer can mistake it for a worker-executed job -- while keeping the zero-cost pre-creation refusal unchanged.

## Decision / result

- `automation/render_lifecycle.py`: new `build_exact_artifact_refusal_result()` (single choke point for the structured shape: `status=infrastructure-blocked`, `permanent=True`, artifact/run/digest/name/source-sha, `has_known_advisory`, issue/run correlation, doc links; never raises; garbage yields a minimal fail-closed record; deliberately distinct from runner `succeeded`/`failed`/`timed_out` job payloads so `parse_job_result`/poll consumers cannot mistake it for a worker-executed job).
- `automation/render-job.sh`: the exact-artifact gate now writes that record to `$RENDER_RESULT_FILE` (best effort, never masking the refusal) while still creating no Render service and exiting 1.
- `automation/test_render_lifecycle.py`: new `test_build_exact_artifact_refusal_result_is_structured_and_permanent` -- structured fields, permanent marker, advisory flag, runner-status distinctness, unknown/garbage fail-closed behavior.
