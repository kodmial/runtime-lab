## Reusable knowledge

- Always verify the full checksum chain for fork artifacts (issue archive digest, then bundled `.sha256`, then expected binary digest, then `--version`): the corrected artifact passes all four links, which is what distinguishes it from the superseded issue-109 build.
- A `max`-stall count in the thousands with `oom_kill 0` and a clean exit is the throttle signature of a marginal fit: the workload completes but lives at the ceiling edge, and the same run could OOM on a noisier host. Record the `max` count, not just the peak, when classifying boundary trials.
- `memory.peak` can read slightly above `memory.max` (~1.3 MiB here) on a surviving container; an over-limit peak alone without `oom_kill`/nonzero exit is throttling evidence, not an OOM verdict.
- Confine agent trials to a container-mounted workdir: the unconstrained host run roamed the whole checkout (60 harness grep matches, 782 MiB tree peak) and had to be discarded as classification evidence, while the container-confined trials stayed on-task (~50 s each).
