## Preconditions / changed premise

Material premise changed since the issue #73 repair: run 36493316814 is the first live run to exercise the storm breaker FIRING on a quiet-counter storm. Both prior live storms that shaped the detector carried massive same-instance stall surges (+430,890 in run 36439192645; +129,597 in run 36442675039), so the replacements-only branch (pinned usage plus repeated transitions with no surge) was never live-validated, and no durable record ever had to justify a pressure verdict against quiet counters. Fully offline; no live Render credentials or service used. Source issue #106 was not closed or modified.

## Observations

- The failed run behaved exactly as designed by the issue #71/#73 repairs up to the terminal error: correct fail-fast classification (3 consecutive unknown-job 404s per loss), correct health qualification (healthy at every proven loss), correct restart proof (instance rotation on all four losses, including three where the replacement reported a numerically larger uptime -- the issue #41 rule), correct three resubmissions on the same worker, correct abandonment at the fourth proven loss instead of burning the 140-poll budget.
- The durable record contradicts the verdict on its face: the human summary prints only global first/last event deltas (0 across replacements by design -- the signal issue #71 explicitly discredited) and omits the deciding inputs (pinned ratio 0.99997, 4 transitions, within-group surge 448 vs the 10000 threshold, the replacements branch). The storm line prints bare `stall_surge=448` with no threshold and no branch. A future agent reading only the log must reverse-engineer the detector to trust the verdict, and may "fix" the gate in the wrong direction.
- The shell resolves `POLL_STORM_THRESHOLD` from `render_lifecycle` and passes it as argv[2] into the storm snippet, but the snippet never reads argv[2] -- the two layers can silently diverge if the constant ever changes.
- The existing shell storm test pre-seeds three pinned instances with per-group surges of 9000 (< 10000), so it already exercises the replacements branch without asserting it; the new assertions lock that in.

## Interpretation

The execution failure itself is the designed response to a systematic capacity mismatch, not a control-plane malfunction: a ~600 MB agent workload cannot make progress on a 512 MB anytime-restart worker, and failing fast at ~13 minutes with an actionable diagnostic (larger worker or smaller workload) dominates burning the 45-minute budget for zero forward progress. Masking or loosening the gate (e.g. demanding stall surges before abandoning) would reintroduce budget-burn for fast-kill OOMs on evidence no stronger than a hunch -- the protocol forbids guessing, and nothing in the repo adjudicates fast-kill vs platform restarts after the fact. The reusable defect is therefore the verdict's auditability: the breaker decides on gap-tolerant within-group evidence but records only the discredited global deltas, and the shell threshold is decorative. The fix records the decision inputs with the decision, and makes the passed threshold binding. Shrinking the workload itself stays owned by the OpenCode memory track (issues #78-#81, #101 and follow-ups); a larger worker stays a cost decision outside automation scope.

## Reusable knowledge

- A storm verdict must be auditable from the durable record: log the deciding inputs (pinned ratio, transition count, within-group surge) with their thresholds and the deciding branch next to the counters, because global first/last event deltas read 0 across replacements by design and will otherwise make a correct verdict look unsupported.
- The replacements branch of the pressure gate is now live-validated: pinned usage plus repeated instance transitions abandons even with nearly quiet stall counters (run 36493316814: surge 448 vs 10000 threshold, global deltas 0). Quiet counters do not exonerate a pinned replacement storm.
- A shell-resolved threshold passed into an embedded interpreter snippet must be parsed by that snippet; passing it while ignoring it creates a silent divergence risk. Corrupt thresholds fail open toward recovery.
- Shell/HTTP storm fakes with per-group surges below the surge threshold exercise the replacements branch -- assert the branch explicitly so the coverage is intentional.

## Unresolved questions / next experiment

A larger Render plan remains a cost decision outside automation scope (free-tier guard unchanged).
