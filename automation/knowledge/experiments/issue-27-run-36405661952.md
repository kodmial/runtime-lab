# Added stale ephemeral Render worker reconciliation watchdog

## Hypothesis / objective

Normal in-process cleanup is insufficient as the only protection against orphaned external resources because a hard process/job/controller termination can prevent that cleanup code from running. A second, independent reconciliation layer can safely remove only stale Runtime Lab ephemeral workers without risking unrelated Render services.

## Prior knowledge consulted

The existing ephemeral-worker naming convention, cleanup semantics, one-worker-per-attempt invariant, controller identity, and the live smoke failures already recorded for issue #9.

## Preconditions / changed premise

This was an independent offline reliability task. No live Render service or credentials were required.

## Procedure

Implemented a reusable watchdog/reconciliation module and an offline test suite. The module classifies services, parses Runtime Lab issue/run correlation, evaluates staleness with an age threshold and active-lease protection, produces dry-run plans, and reuses bounded delete/verify/suspend-fallback cleanup semantics.

## Observations

- Only names matching the strict Runtime Lab ephemeral shape are automation-owned candidates.
- The persistent `runtime-lab-controller` is explicitly excluded.
- Malformed lookalike names, unrelated services, missing/invalid/future timestamps, and lease-check failures fail closed.
- Old automation-owned workers can be selected while young or active workers are skipped.
- Cleanup is delete-first and requires authoritative absence verification.
- Failed deletion can use bounded suspend fallback and retry.
- Multiple stale workers are handled independently.
- The watchdog exposes no worker-creation path and the tests require no network.

## Interpretation

The system now has a second cleanup line that does not depend on the original worker-owning execution surviving long enough to run its local `finally`/cleanup path.

## Decision / result

Keep normal per-attempt cleanup as the primary mechanism and use stale-worker reconciliation as independent defense-in-depth. Reconciliation must remain strictly scoped to provably automation-owned ephemeral services.

## Validation

Issue #27 completed through PR #30 and merge commit `afdd048037d18cabe5cb87a095f95fd309eec484`. The implementation includes a dedicated offline unit test suite.

## Reusable knowledge

External-resource cleanup needs both local ownership cleanup and an independent orphan reconciler. The reconciler must be fail-closed about ownership rather than delete by a broad prefix.

## Unresolved questions / next experiment

Wire reconciliation into the persistent controller/watchdog scheduling path after the direct Render cutover, while preserving active ownership/lease checks.
