## Preconditions / changed premise

Material premise changed since the issue #119 repair: run 36498921649 is the first live run to exercise source issue #110 AFTER the exact-artifact gate landed (base `0ce27b7`, which contains both the `f84a0cf` gate and the #119 parser fixture), while run 36497358708 executed pre-gate base `34d412e`. This repair runs at base `0ce27b7`. The failed run is therefore live confirmation that the gate refuses #110 pre-creation in seconds with zero Render cost -- not evidence that the gate is broken, and not a repeat of the pre-gate storm. Source issue #110 was not closed or modified.

## Observations

- The failed run behaved exactly as designed: the pre-creation gate detected the full conjunction (numeric artifact id + numeric source workflow run + sha256 digest) in #110's phrasing, refused before any Render API creation call, and cleanup correctly found nothing to delete.
- The refusal diagnostic names the artifact (`11001896223`), the source run (`36492639568`), the expected archive digest, and the missing delivery capability (no credentialed artifact fetch on the worker, no artifact selection in the submit-job payload, credential-scrubbed child env).
- Parser check on the live #110 body at this base commit recovers artifact `11001896223`, run `36492639568`, archive digest `8d5c5c3e...`, source SHA `8ed6c749...`, artifact name `opencode-coding-linux-x64`.
- New shell test with faithful #110 phrasing (Source workflow run / Artifact ID / Artifact archive digest / Source SHA / retention-expiry line) reproduces the live refusal offline: nonzero exit, `infrastructure-blocked` naming artifact and run, zero `api.render.com/v1/services` calls, no state file, empty result file.
- Ordinary smoke bodies without the conjunction still parse to None, so legitimate baseline runs are never refused.

## Interpretation

The execute=failure outcome for run 36498921649 is the gate working correctly, not a lifecycle defect: storm detection, resubmission, polling envelope, and cleanup never engaged because no worker could honestly test what #110 requires. The reusable defect class -- silent wrong-binary substitution for exact-artifact qualification issues -- stays repaired. The remaining gap this run exposed is regression depth, not logic: only #106 phrasing was locked at the shell level, so a future refactor could break #110 coverage while the #106 shell test still passed. The honest repair is to lock #110's exact refusal path at the shell level and to guard the fail-closed gate against over-blocking ordinary smoke.

## Reusable knowledge

- Run 36498921649 is the first live post-gate datapoint for #110: the exact-artifact gate refuses the #110-phrased contract pre-creation in seconds with zero Render cost (execute=failure, cleanup=success, no service), versus the ~11-minute four-restart substituted-binary storm the same contract burned pre-gate.
