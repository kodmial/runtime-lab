## Interpretation

- The registry is now data, not a second gate: PR #12 validation is byte-identical (fully pinned), PR #15 adds one more pinned binary/version/source row whose transport ids are publish-time values. Requiring the PR #15 binary digest in the issue body is what keeps arbitrary numeric artifacts out while letting the published PR #15 artifact through without a post-publish code change.
- Path-shape acceptance (numeric ids) is not authorization: the superseded artifact stays rejected at the path layer, and execution still requires the full `validate_exact_identity` conjunction plus controller-side archive->binary->version re-verification before any push, so a staged path alone never executes.
- The handoff ordering (exact fields into the issue BEFORE unpause, then explicit scheduler + executor dispatch) is what makes Render start without user/chat intervention; citing #134 marginal as evidence-only in the body prevents any downstream classifier from re-gating the candidate on Docker throttling.
- Credentials stay controller-side by construction (bytes-only push, scrubbed child env, no credential in the handoff plan), identical to the #128 guarantee.
