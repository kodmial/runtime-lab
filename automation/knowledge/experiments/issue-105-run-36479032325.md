# Qualify coding-only OpenCode PR #10 in GitHub Actions under 512 MiB

## Hypothesis / objective

The real coding-only variant from `kodmial/opencode#10` (branch
`coding-only-lite-issue-101`, required head
`d604c215c2c691c4ad79bd59d1ea2c5d76f5c8aa`, build
`bun run --cwd packages/opencode build:coding`, binary
`packages/opencode/dist/coding/bin/opencode-coding`) can be built and
qualified in GitHub Actions under a real 512 MiB no-swap limit
(`--memory=512m --memory-swap=512m`, `BUN_OPTIONS=--smol` as a labelled
A/B arm): exact source SHA + binary SHA-256 recorded, `--version` smoke,
dependency-graph proof that the dedicated entrypoint drops the normal
TUI/web/serve/MCP command table, a real representative coding workload
(search + edit + shell/build/test), full cgroup/process measurements,
direct comparison with the ~600-615 MB baseline from issue #52, and at
least two constrained real-agent trials. Verdict: reliable under 512
MiB, marginal, or does not fit. Success is never claimed from
`--version`, a fake agent, or an unconstrained run. A compile defect in
PR #10 at the required SHA is a concrete qualification failure with the
exact error recorded.

## Observations

- Required SHA does NOT build (directly seen, exact errors):
  - `bun install --frozen-lockfile` fails: `No version matching
    "7.0.5" found for specifier "@types/turndown"`. The PR's
    `packages/opencode/package.json` hunk bumps `@types/turndown`
    5.0.5->7.0.5; npm lists only 5.0.x (latest 5.0.6). Reverting that
    one hunk to 5.0.5 (matches `bun.lock`) lets install complete
    (2333 packages).
  - `bun run --cwd packages/opencode build:coding` then fails:
    `Could not resolve:
    "@ff-labs/fff-bin-linux-x64-glibc/libfff_c.so"`. The full
    `script/build.ts` defines `FFF_LIBC` as `"gnu"`/`"musl"` and
    prefetches all-OS fff binaries (`bun install --os="*"
    --cpu="*"`); `script/build-coding.ts` defines `FFF_LIBC "glibc"`
    (no such package dir; installed is `...-gnu`) with no prefetch.
    One-word fix `glibc`->`gnu` unblocks codegen. (A tarball-only
    `git branch --show-current` exit-128 was bypassed with
    `OPENCODE_VERSION=1.18.33 OPENCODE_CHANNEL=latest`.)
- Diagnostic binary (required head + the two /tmp-only fixes, clearly
  labelled, never the qualification artifact): 157,840,864 bytes
  (~27.5 MB smaller than upstream 185,354,368), SHA-256
  `d6c51699a6cff6f0062402ee2f7403b98b8817c187e5ed02fd7627a96c2f4d33`,
  `--version` reports `1.18.33`.
- Dependency graph (directly seen): coding entry imports only
  `yargs`, `yargs/helpers`, `./cli/cmd/run` (`RunCommand`),
  version, `./cli/heap`; full `src/index.ts` carries tui/web/serve/
  acp/attach/mcp. Binary `--help` lists only `opencode-coding run`.
  The Stage-A cut is real; the `RunCommand` transitive closure
  (MCP/LSP/formatter/plugins/skills/web) is not yet pruned per the PR
  body.
- Non-success signals only: host `--version` peak tree 137,776 kB
  (~134.5 MiB, ~60-70 MB under upstream); Docker 512m `--version`
  passes (cgroup peak 55,427,072 B, `oom 0`).
- Real workload, host (diagnostic binary, FOO_LIMIT 10->20 repo):
  peak tree 551,560 kB (538.6 MiB), family 4, exit 124 (timeout 420
  s). The edit landed on disk (`FOO_LIMIT = 20`) with pytest cache
  present, but the process never exited within budget.
- Constrained trial 1 (Docker 512m/no-swap, `BUN_OPTIONS` unset):
  cgroup peak 537,026,560 B (512.15 MiB, pinned at the 536,870,912
  ceiling), current 420,884,480 B, `max` 592 stall events, `oom_kill`
  0, agent RSS ~372 MB. Edit landed; no clean exit within 450 s
  (telemetry read live via `docker exec`, container then killed).
- Constrained trial 2 (Docker 512m/no-swap, `BUN_OPTIONS=--smol`):

  `max` 581, `oom_kill` 0, agent RSS ~367 MB (~5 MB under the unset

- Baseline comparison: #52 host peak 614,632 kB (600.2 MiB). The

- Tests: 12/12 new harness tests pass; full offline suite run at the

## Interpretation

- At the exact required SHA, PR #10 is a concrete qualification
  failure: it cannot be installed or compiled as specified. Both
  defects are small and local to the coding-only branch (one
  dependency version, one libc define), matching the issue's
  fix-and-rerun clause — but pushing that fix to `kodmial/opencode#10`
  belongs to the workflow/fork pipeline (this run performs no pushes),
  so the fingerprinted verdict stays tied to `d604c21` until the fork
  lands a new head SHA.
- Even past the build defects, the diagnostic measurements falsify the
  512 MiB goal for Stage A: the real coding workload peaks above the
  limit on host and pins the cgroup ceiling with hundreds of `max`
  stall events in both A/B arms, with no clean exit inside a 450 s
  budget. `BUN_OPTIONS=--smol` moves ~5 MB, not the ~25+ MB overage.
  The entrypoint cut saves real memory (~63 MB vs baseline) but the
  remaining `RunCommand` closure still does not fit.
- The repeated hang-past-budget (edit done, process alive) in all
  three agent runs is a second reliability signal, not a measurement
  artifact: work completes but the agent never reports back. It is
  recorded as correctness `fail` (no verified completion), not hidden.
- No success is claimed from `--version` (134 MB), the smoke control,
  or the unconstrained host peak; the verdict rests solely on the two
  constrained real-agent trials plus the host over-limit peak.

## Decision / result

Outcome `failed` (definitive negative verdict, not missing evidence):

- **does not fit** under 512 MiB/no-swap. The exact PR #10 head
  `d604c215c2c691c4ad79bd59d1ea2c5d76f5c8aa` does not build
  (frozen-install + FFF_LIBC defects recorded exactly), and the
  diagnostic binary built from that head plus two minimal local fixes
  still exceeds the limit on the required workload (host 538.6 MiB;
  both 512m/no-swap trials pinned at the ceiling with `max`
  581-592 events and no clean exit; `--smol` saves ~5 MB).
- Deliverables: exact fork SHA + diagnostic binary SHA-256/size
  above; Actions run
  `https://github.com/kodmial/runtime-lab/actions/runs/36479032325`;
  reproducible commands in `automation/opencode_coding_qualify.py`
  (`build_steps_for_pr`, `docker_trial_command`) and the benchmark
  JSON; A/B table and baseline gap in the JSON; correctness result
  (edit landed, no verified completion); explicit engineering verdict
  (does-not-fit; fix the two build defects on a new fork SHA, then
  continue source-level reduction of the `RunCommand` closure — Stage
  A alone cannot close the gap).
- The separate Render Free issue must test the same fingerprinted
  artifact only after the fork lands a buildable head SHA; there is
  nothing buildable at `d604c21` to promote to Render.

## Reusable knowledge

- PR #10's two build defects and their minimal fixes (turndown
  5.0.5 revert; `FFF_LIBC` `glibc`->`gnu` mirroring `script/build.ts`)
  — check these first on any new coding-branch head SHA before
  burning builder time.
- `OPENCODE_VERSION=1.18.33 OPENCODE_CHANNEL=latest` deterministically
  bypasses the git-dependent `Script.channel` path for tarball/CI
  builds without a `.git` directory.
- Stage-A entrypoint shape provably drops ~22 top-level commands and
  ~60-70 MB startup RSS, but only ~10% off the real-agent peak; the
  `RunCommand` transitive closure is where the remaining ~25+ MB
  overage lives.
- `BUN_OPTIONS=--smol` is a ~1% (~5 MB) effect on this workload here,
  not a path to 512 MiB; always record it as a labelled arm.
- Live-container `docker exec` cgroup reads salvage the peak/current/
  events verdict when the agent hangs past the client budget; always
  kill the container afterwards and record the missing clean exit as
  correctness `fail`, never as success.
