# Land the offline qualification gate; live Render matrix blocked on #58/#86

## Hypothesis / objective

A stdlib-only offline qualification gate can encode the complete #81 contract
(workload matrix, per-run measurement fields, fail-closed verdict, budget
evaluation, before/after table, production start command/config/fingerprint)
while reusing the #57 cgroup telemetry vocabulary and the #58 Render execution
path, so the later live `execution:render-smoke` run executes the matrix
without building a second measurement stack. The validated pre-optimization
baseline already fixes the exact gap a fork artifact must close, so this run
also reports that gap and the dominant memory class instead of masking the
blocked live verdict with retries or fabricated runs.

## Interpretation

- The live #81 verdict cannot be produced in this run: the matrix needs a
  real Free worker (#58 path) and an immutable fork artifact (#86), and
  neither exists yet. Reporting anything else would be fabrication, so the
  honest terminal verdict for this run is inconclusive (blocked), not a pass.
- The offline gate is still the correct complete deliverable for this run:
  it locks the matrix, the measurement contract, the fail-closed verdict,
  and the budget math in tested code, so the future live run collects
  comparable evidence with the existing #57 sampler instead of inventing new
  fields under schedule pressure.
- The baseline gap bounds the fork work: ~150 MiB must disappear for the
  preferred target, ~88 MiB even for bare survival at the hard limit, and the
  dominant class (Bun anon mmap) means the win must come from the #77
  source-level removal order, not configuration or allocator tricks. Whether
  the #78 config-only profile closes any measurable part of that gap remains
  a live measurement, not an assumption recorded here.

## Reusable knowledge

- Qualification-gate pattern: encode the workload matrix, the exact
  measurement field contract, and the fail-closed verdict in tested
  stdlib-only code before the live run, reusing the existing telemetry
  vocabulary (`cgroup_memory` keys + sampler summary keys) so live evidence
  stays comparable and no second measurement stack appears.
- Gate-verdict separation: hard failures (OOM kill, worker replacement,
  nonzero exit, unverified cleanup) reject in validation; preferred-target
  headroom (450 MiB) is reported as an exact gap by budget evaluation, never
  as a pass/fail mask.
- Blocked-live-run honesty rule applied: when blockers (#58/#86) are OPEN
  and the execution path lacks Render credentials, record `inconclusive`
  with the exact missing premises and the quantified baseline gap rather
  than claiming a partial qualification.
