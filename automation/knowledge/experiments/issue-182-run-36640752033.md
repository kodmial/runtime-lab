# Expose the finalize hold branch as an executable CLI (repair run 36640697494)

## Hypothesis / objective

Run 36640697494 (source issue #106, smoke) failed in `render-job.sh` at the
exact-artifact pre-creation gate with `infrastructure-blocked` for the retired
artifact `11001896223` (workflow run `36492639568`) plus the known-artifact
advisory plus the superseded redirect to successor `11004835952`, after zero
Render service calls (execute=failure, cleanup=success). Objective: identify
the root cause from log evidence, fix the reusable defect so this failure
class stops minting one P0 repair per redispatch, regression-lock it, and
keep the change scoped (no workflow edits, no git mutations, no source-issue
#106 changes).

## Preconditions / changed premise

Material premise vs the #177 repair (run 36638450066 at base `54a4e90`,
which lacked any executable finalize branch): the failed run 36640697494
executed at head SHA `35fb646` (verified via `gh run view --json
headSha`), which already contains the #177 `finalize_repair_decision` +
`format_hold_notice` library -- and the downloaded durable evidence proves
the branch answers correctly offline (`dispatch_hold.held=true` /
`verdict=held-superseded` in `render-qualification-106-36640697494`, and
`finalize_repair_decision` on those exact bytes returns `action=hold`
with the successor notice). Yet finalize still minted repair #182. This
falsifies the hypothesis that specifying the branch in library code stops
the loop: the provisioned envelope cannot call library code without
hand-rolling the repair-count/duplicate/exhausted plumbing in bash, which
is exactly the registry duplication the hold series exists to avoid. Per
protocol this repair does not repeat any producer-signal or library-branch
experiment; it exposes the same branch as an executable CLI over inputs
the finalize step already holds. Source issue #106 was not closed or
modified. This run creates no Render service (no executor envelope here
by design).

## Interpretation

- The execute=failure outcome for run 36640697494 is the executor gate
  working correctly at HEAD, not a lifecycle defect: no worker could
  honestly test what #106 requires, so refusing pre-creation in seconds
  at zero cost is the only honest behavior.
- The reusable defect is exposure, not signal or branch logic: the
  retirement answer now exists in six producer forms (eligibility
  mirror, log verdict, structured record key, hold CLI, branch library,
  notice formatter -- all proven live or offline against real failure
  bytes) yet none of them is callable from the provisioned finalize step
  without reimplementing envelope plumbing. The `--finalize` mode moves
  that last call boundary into `automation/` behind a pure, tested
  contract over inputs the finalize step already holds (result file,
  repair count, budget, open-repair marker, source/failed-run ids), so
  the provisioned envelope adopts the hold with one call instead of
  duplicating the registry.
- The gate stays deliberately fail-open toward today's behavior: garbage
  content classifies as mint/duplicate/exhausted by the count inputs and
  a missing result file is a usage error (fall through, never suppress);
  only an explicit registry-backed hold (artifact/run pair in
  `SUPERSEDED_WORKFLOW_ARTIFACTS`) returns hold.

## Reusable knowledge

- A branch helper the envelope cannot execute is not a fix: run
  36640697494 executed at a base containing `finalize_repair_decision`
  yet still minted #182. Ship consumer branches as executable CLIs over
  inputs the envelope already holds, with one JSON payload and stable
  exit codes provisioned steps can key on without embedding registry
  logic or hand-rolling count plumbing.
- Keep suppression narrow and fail open at every layer: only a
  registry-backed hold skips minting; garbage content follows the count
  inputs toward today's behavior and missing files are usage errors, so
  a corrupt input can never suppress a legitimate repair.
- Keep the registry the single source of truth at the consumer too:
  re-validate the held pair against `SUPERSEDED_WORKFLOW_ARTIFACTS`
  before returning hold, so stale or hand-crafted decisions degrade to
  mint/duplicate/exhausted instead of redirecting triage.
