## Preconditions / changed premise

Material premise vs the #161 repair (run 36632062583 at base `49a985b`,
which lacked the hold verdict): the failed run 36633812500 executed at base
`fe1811d`, which already contains the #161 `held-superseded` log verdict,
and the log proves it fired. Yet the durable refusal evidence uploaded as
`render-qualification-106-36633812500` carries no hold marker -- only
`permanent`/`superseded`/`successor`. So the new, directly observed gap is
not the verdict (which exists) but its durability: the hold is log-only,
and any consumer of durable evidence must scrape log text to tell a held
retired contract apart from a merely undeliverable one. Per protocol this
repair does not repeat the #161 log-verdict experiment; it promotes the
same verdict into the structured refusal record from the same single
registry. Source issue #106 was not closed or modified. This run creates
no Render service (no executor envelope here by design).

## Interpretation

- The execute=failure outcome for run 36633812500 is the executor gate
  working correctly at HEAD, not a lifecycle defect: no worker could
  honestly test what #106 requires, so refusing pre-creation in seconds
  at zero cost is the only honest behavior.
- The reusable defect is evidence-side: the retirement hold now exists
  in three places with three different durabilities -- the
  `decide_eligible` mirror (unconsulted live, per #161), the log verdict
  (ephemeral, 30-day artifact log retention at best), and the structured
  refusal (durable, uploaded per run) -- but only the durable record
  survives for triage and provisioned-envelope keying, and it lacked the
  hold. Promoting the verdict into `dispatch_hold` from the same
  registry keeps one source of truth for "retired" while giving durable
  consumers a stable key (`dispatch_hold.held` / `.verdict`) that never
  requires log scraping.
- The change is deliberately additive and verdict-preserving: existing
  refusal keys are byte-identical in shape, ordinary and unknown-contract
  refusals carry an explicit not-held verdict with an empty successor so
  they never misdirect, and garbage input still never raises.

## Reusable knowledge

- A verdict that exists only in logs is not durable evidence: run
  36633812500 proved the #161 hold fires yet leaves no trace in the
  uploaded refusal artifact, so durable consumers cannot key on it.
  Hold verdicts must ride the structured result record from the same
  registry as the log line.
- Additive record extension beats shape change: existing
  `permanent`/`superseded`/`successor` consumers
  (`refusal_retirement`, qualification classifier, triage) keep working
  untouched while new consumers key on `dispatch_hold`.
- An explicit not-held verdict with an empty successor is safer than a
  missing key: ordinary and unknown-contract refusals assert "not
  retired" instead of leaving consumers to infer it from absence.
