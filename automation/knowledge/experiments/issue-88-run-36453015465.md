# Enforce the OpenCode-fork optimization dependency DAG before dispatch

## Hypothesis / objective
Free-form body text such as "Blocked by #76" is not honored by either
scheduler path (Actions `issue-scheduler.yml` honors only native
`blocked_by` plus the DoR `#N is completed` fallback; the controller in
`automation/render_controller.py` mirrored exactly that), so dependent
OpenCode optimization issues could be reserved/dispatched before their
prerequisites complete. Enforcing the issue-#88 DAG in the mechanism each
scheduler actually honors closes that gap without a global mutex.

## Interpretation
The previous defect was structural, not textual: both schedulers ignored
"Blocked by #N" prose, native edges were empty, and the DoR fallback
required the `#N is completed` phrasing the optimization issues do not
use. The fix is therefore two-layered: native `blockedBy` edges give the
Actions scheduler the mechanism it honors, and the controller's enforced
DAG gives the same graph even when the native API is unavailable or a
body never used the fallback phrasing. Fail-closed unknowns plus the
blockers-before-reservation ordering guarantee a dependent cannot receive
`automation:in-progress` while any enforced prerequisite is open, while
per-issue (not global) gating keeps #76/#85 parallel and #88 independent.
Pause removal keyed strictly on enforced satisfaction plus the #89 pin
prevents premature unpausing.

## Reusable knowledge
- Scheduler gating rule: only native `blockedBy` and the DoR `#N is
  completed` phrasing gate dispatch; "Blocked by #N" prose is inert. Any
  real prerequisite must exist as a native edge AND (for the controller
  path) in the enforced DAG module.
- Enforced-DAG pattern: keep the graph in one stdlib module with
  fail-closed unknowns, merge enforced blockers before the reservation
  gate, fetch prerequisite states in `build_snapshot`, reconcile pauses
  only on enforced satisfaction, pin contingencies like #89, and keep all
  gating per-issue so unrelated work stays parallel.
- Live readout: GraphQL `blockedBy(first:N) { nodes { number state } }`
  is authoritative; `gh issue view --json` shows no dependency field.
  Closed issues accept `blockedBy` edges for historical record.
