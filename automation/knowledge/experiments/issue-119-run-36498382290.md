## Observations

- The failed run behaved as designed up to the terminal error: healthy runner at every proven loss, instance-id-first restart proof on all four losses, three same-worker resubmissions, audited abandonment at the fourth proven loss (poll 33/140) instead of burning the budget.
- The storm verdict is a true positive: usage pinned at ratio 1.0000 with 4 instance transitions satisfies the replacements branch; the quiet stall surge (359 vs 10000) does not exonerate a pinned replacement storm per the run-36493316814 precedent. Loosening the breaker is excluded.
- The executed binary was the baseline pinned binary, not the required exact artifact (deduced, not guessed): (a) no code path at base `34d412e` conveys a workflow artifact to the worker; (b) the issue-109 trials prove the exact `0.0.0` artifact fast-fails in ~3 s with sub-ceiling peaks and zero pressure events, while this run stormed ~11 minutes pinned at the ceiling -- the baseline agent's fingerprint; (c) the worker holds no GitHub credential capable of the authenticated artifact download the issue demands.
- Net effect: ~11 minutes of Render time plus four restarts were burned on a run that could never test what the issue asked, and the failure was misattributable to the artifact under test.
- At this base commit (`f84a0cf`) the live #110 title+body parses to the full exact-artifact requirement and the blocker names the artifact, run, digest, and missing delivery capability.

## Interpretation

The storm abort is the designed response to a systematic capacity mismatch; the reusable defect -- silent wrong-binary substitution for exact-artifact qualification issues -- was already repaired by the `f84a0cf` gate (built for #106/#115) but after this run started. The remaining gap for #119 is coverage, not logic: the gate's regression tests used only #106 phrasing, while #110 phrases the same contract differently ("Source workflow run", "Artifact ID", "Artifact archive digest", retention-expiry line). The honest repair is to prove the existing gate covers #110 and lock that proof in as a regression test, rather than inventing a second gate or re-burning a worker.

## Reusable knowledge

- The exact-artifact gate covers every issue carrying the full conjunction (numeric artifact id + numeric source workflow run + sha256 digest) regardless of label order or surrounding lines -- #110's "Source workflow run / Artifact ID / Artifact archive digest" phrasing trips the same gate as #106.
- Run-to-merge skew matters for repair attribution: run 36497358708 executed base `34d412e` (pre-gate) even though the gate (`f84a0cf`) is the HEAD parent; always compare the failed run's `headSha` against the fix commit before declaring a recurrence.
- A 11-minute pinned-at-ceiling replacement storm with zero memory.events deltas is the baseline agent's fingerprint, not the exact PR #12 (`0.0.0`) artifact's behavior (seconds-long fast-fail, sub-ceiling peaks, zero pressure events).
