additive fork change in `kodmial/opencode` (dedicated headless
entrypoint/build targets whose static-import graph excludes TUI/desktop/
web UI, MCP, LSP/formatter, unused plugins/skills/web tools while

success claimed from `--version` or a fake workload.

- The PR is a genuine additive source change in `kodmial/opencode`, not a
  Runtime Lab spec sketch: Stage A physically removes the full top-level
  command table (TUI/web/serve/ACP/attach/MCP/UI) from the compiled
  entrypoint and adds a dedicated Linux build, while keeping the proven
  `RunCommand` path (hence the provider/model/session/agent loop and the
  read/search/edit/write/patch/shell tools) and the full build usable.
- Stage A is real but partial against this issue's DoD: because
  `RunCommand` is reused unchanged, the deeper exclusions (MCP,
  LSP/formatter, unused plugins/skills/web tools, unnecessary
  top-level/static imports inside the run path) are not yet pruned from
  the transitive closure — the PR body honestly defers them to later
  stages ("prune remaining indirect imports if necessary"). The 9-file
  patch doc in `automation/` remains the fuller target, not the landed
  state.
- Measurements are separated honestly: `--version` (~200 MB) and the
  Docker ceiling/hog probes are recorded as non-success signals; no new
  live-agent peak is claimed here, and the lite-binary delta is correctly
  deferred (no `bun`, no fork checkout in this worker, so no
  `build-coding` binary was compiled here).
- The remaining DoD gap is environment/ownership, not a contract defect:
  fingerprinting the `d604c21` coding binary, rerunning the representative
  coding-agent peak under 512m/no-swap, and Render Free trials require the
  resourced fork builder / workflow-owned PR pipeline.
