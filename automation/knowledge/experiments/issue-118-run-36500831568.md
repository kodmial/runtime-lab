The failed run is therefore live confirmation that the gate refuses #106 pre-creation in seconds with zero Render cost -- not evidence that the gate is broken, and not a repeat of the pre-gate storm. Per protocol this repair does not repeat the live Render experiment; it locks the demonstrated #106 refusal path to the same diagnostic depth #123 gave #110 (the coverage gap this run exposed: the #106 shell and blocker tests never asserted the advisory even though the #106 contract pins the same immutable artifact). ## Interpretation

The execute=failure outcome for run 36498162815 is the gate working correctly at its base, not a lifecycle defect: storm detection, resubmission, polling envelope, and cleanup never engaged because no worker could honestly test what #106 requires. The reusable defect class -- silent wrong-binary substitution for exact-artifact qualification issues -- stays repaired. The gap this run exposed is diagnostic symmetry, not refusal logic: the advisory map (keyed by immutable artifact id + source run) already fires for #106 at HEAD, but only the #110 tests locked that behavior, so the #106 path could silently lose advisory depth. The honest repair is to lock the #106 phrasing to the same advisory depth at both test layers and to record this run as the first live post-gate confirmation for #106, mirroring what #121/#123 did for #110.
