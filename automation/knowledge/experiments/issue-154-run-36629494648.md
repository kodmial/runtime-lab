## Interpretation

The execute=failure outcome for run `36629441608` is the gate working correctly at HEAD, not a lifecycle defect: storm detection, resubmission, polling envelope, and cleanup never engaged because no worker could honestly test what #106 requires. The reusable defect class -- silent wrong-binary substitution for exact-artifact qualification issues -- stays repaired, and the retirement redirect from #133 plus classifier propagation from #138 stay intact. The gap this run exposed is retirement visibility on the generic repair path: the chain-only fingerprint dedup cannot fire for non-chain smoke issues, so without a choke-point helper the provisioned finalize keeps minting identical P0 repairs after every repair-merge reset. The honest repair is to expose the data-driven retired verdict (`is_retired_exact_artifact_issue` / `retired_exact_artifact_successor` / `should_suppress_render_repair_for_retired`) backed by `SUPERSEDED_WORKFLOW_ARTIFACTS`, so the separately provisioned finalize can keep the source paused and follow the successor instead of re-investigating identical text.
