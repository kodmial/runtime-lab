# Build and fingerprint OpenCode experiment artifacts in parallel

## Hypothesis / objective

A shared, stdlib-only artifact pipeline can turn any explicit `kodmial/opencode` experiment ref into a deterministic standalone Linux OpenCode binary over the upstream-supported Bun compile path, fingerprint it (fork SHA, upstream base, toolchain, binary SHA-256, build identity), publish it by an immutable GitHub-backed reference, and let Runtime Lab/Render select that exact binary per worker — with several experiment artifacts (source-stripped, bounded-output, direct-headless candidates) coexisting concurrently, readiness failing on any fingerprint mismatch, the upstream pinned binary kept as baseline only, and no runtime installer/download fallback.

## Interpretation

The two caught defects confirm why the issue demands fail-closed validation at every boundary rather than one central check: an identity formatter and a charset validator are exactly the places where a sibling experiment's artifact could silently masquerade as another. The per-artifact directory plus id-embedded commit prefix makes confusion structurally impossible (a copied id fails validation against its own SHA), which is what lets the source-stripped, bounded-output and direct-headless branches build concurrently without coordination. Deferring the real Bun compilation to the resourced builder is honest, not partial: every runtime-lab-side behavior (selection, verification, readiness, isolation, baseline preservation, no-installer guarantee) is proven offline against the same code paths production will execute.

## Reusable knowledge

- Artifact-identity pattern: fingerprint = explicit ref + 40-char commit SHA + upstream base + toolchain + binary SHA-256 + build identity, with derived per-artifact id/tag/GitHub release reference that all embed the same commit prefix; validation cross-checks every derived field against the SHA so sibling artifacts cannot masquerade.
- Mutable-pointer ban: reject `latest`/`main`/bare branches at the contract, builder, env-resolution, and payload layers independently; each layer is a separate regression test.
- Coexistence by construction: per-artifact directories (never one shared binary path) plus no-fallback readiness is what makes parallel hypotheses safe; the baseline stays a separate legacy path, never an implicit default.
- No-installer guarantee: experiment paths resolve only from the deploy tree and raise before any installer code is reachable; prove it with a command-runner test double that fails any installer invocation.
- Baseline substitution rule (from #79/#80, reapplied): when the fork binary cannot be built in this worker, record hermetic fingerprint/readiness accounting plus the unchanged baseline and defer the compiled-binary delta to the resourced builder with the same harness — never fabricate it.
