# Render-qualify the exact published OpenCode PR #15 artifact (pins, gate, controller proof)

## Hypothesis / objective

Issue #141 demands the already-measured exact OpenCode PR #15 binary run on a real Render Free 512 MiB worker through the real exact-artifact path (controller-side credentialed fetch, archive+binary verification, deterministic absolute-path launch, `/proc/<pid>/exe` proof, verified cleanup), with Docker-only evidence explicitly insufficient and the #134 Docker `marginal` verdict explicitly not a gate. Objective of this run: make the automation accept and route the exact published #141 transport (artifact `11009286301` from source run `36512250023`, archive `sha256:df547ac8...313c46`, binary `d9f930c1...45f0c0`, `1.18.33`) end to end, verify every controller-side identity claim live, and leave the worker execution plus machine-readable result marker to the `render-executor.yml` envelope that owns the Render credential and the 55-minute budget.

## Preconditions / changed premise

Material premise changed vs #134: the qualification subject is no longer the locally built #134 binary (171,222,496 B, SHA-256 `4e310bbd...28ded`) but the published immutable Actions artifact `11009286301` from source run `36512250023` (archive `sha256:df547ac8...313c46`, binary 171,218,400 B, SHA-256 `d9f930c1...45f0c0`, `--version 1.18.33`). Same source head (`842157c3...`), same build command, ~4 KiB rebuild drift: Bun compiles are locally deterministic but not reproducible across build environments (per the issue-#144 topic note), so binary identity must be pinned per published build. This run does not repeat the #134 Docker trials or the #140 publish; it re-pins the code to the published identity, locks the #141 transport through the gate with a regression test, and verifies the artifact live controller-side. No Render worker is created here by design: this 35-minute code job holds no Render credential (`KEY` lives only in the `render-executor.yml` envelope) and owns no cleanup step, so creating a service here could strand an automation-owned worker and violate the one-service global invariant.

## Interpretation

- The code defect class is closed: before this run the size gate (`BINARY_BYTES = 171222496`) and several docstrings still pinned the superseded #134 local-build identity while the delivery registry already pinned the published `d9f930c1...45f0c0` binary, so a strict reader (or a size-checking verifier) saw two different PR #15 binaries. All layers now name one published identity.
- The controller half of the #141 contract is proven against the live artifact, not just against offline fixtures: metadata, archive digest, payload shape, binary digest, size, version, run-only boundary, and provenance metadata all match the issue exactly with no rebuild and no substitution.
- The worker half (real 512 MiB coding workload, `/proc` proof, `memory_telemetry`, result marker, verified absence) is implemented but not executed here: `render-job.sh` already fetches with the controller credential, pushes bytes only, launches the deterministic absolute path with zero fallback, and `record_render_qualification.py` already classifies identity/memory/correctness/infrastructure for artifact `11009286301`. Execution requires the executor envelope's credential and budget, so the honest verdict is `inconclusive`, not a premature `succeeded`.
