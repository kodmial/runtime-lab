# Built schema-validated experiment catalog and query CLI

## Hypothesis / objective
A schema-defined, deterministic, machine-readable catalog derived from the immutable per-run records lets a new agent discover prior experiments with one offline local command before reading full Markdown records, without introducing a shared hot-file index, a database, or a Render service.

## Prior knowledge consulted
- `automation/knowledge/PROTOCOL.md` (READ -> PLAN -> EXECUTE -> RECORD -> PROMOTE; per-run unique files; records immutable after merge).
- `automation/knowledge/topics/agent-execution.md`, `render-lifecycle.md`, `scheduler-recovery.md` (durable memory boundary; observation/interpretation/decision split).
- `automation/knowledge/decisions/ADR-0001-repository-agent-memory.md` (Git as handoff boundary; per-run files avoid append conflicts).
- All five existing experiment records for issues #9, #27, #28, #31 (YAML-style front matter shapes, topic/outcome vocabulary, evidence conventions).
- `automation/render_lifecycle.py` hard-gate validator (`validate_experiment_record_text`) and its workflow/runner enforcement points.

## Preconditions / changed premise
No prior catalog or JSON metadata existed: every record used YAML-style front matter and discovery required reading full files. This run introduces the strict-JSON contract, so migration of the five existing records (meaning preserved, representation tightened) is a new premise, not a repeat of any prior experiment. Fully offline; no Render credentials or live service involved.

## Procedure
1. Read the protocol, topic notes, all prior experiment records, the hard-gate validator, and the workflow knowledge gate.
2. Added `automation/knowledge/schema/experiment.json` and `catalog.json` declaring JSON Schema Draft 2020-12 contracts for record metadata and the derived catalog.
3. Implemented stdlib-only `automation/knowledge_catalog.py` with `validate`, `build` (stdout default, optional explicit `--output`), and `query` (`--issue`, `--topic`, `--outcome`, `--record-id`, composable AND) plus deterministic serialization and fail-closed integrity checks.
4. Migrated the five existing records to strict JSON front matter with derived `record_id` values, preserving bodies byte-for-byte.
5. Updated `automation/knowledge/PROTOCOL.md` (READ starts with the catalog query CLI; JSON template; derived-catalog section) and rewired `render_lifecycle.validate_experiment_record_text` to the strict JSON format via `knowledge_catalog` without weakening required-section validation.
6. Added `automation/test_knowledge_catalog.py` (27 offline tests) and updated the legacy record helper in `automation/test_render_lifecycle.py` to the JSON form.
7. Promoted reusable discovery facts to `automation/knowledge/topics/agent-execution.md`.

## Observations
- `validate` passes over the five migrated records; repeated `build` output is byte-identical (`cmp` clean); `query --issue 9` returns the two issue-9 failures in record_id order.
- Full suite: 268 passed (241 pre-existing plus 27 new), including the updated hard-gate tests.
- Duplicate `(issue, run_id)` is unreachable through distinct filenames (filename encodes both), so the duplicate guards are exercised via entry-level and listing-level tests as defense-in-depth; filename-agreement checks fire first on real disk layouts.
- `git status` shows only intended source/record changes; no generated index, no Render resources.

## Interpretation
The derived-catalog model holds: per-run Git records stay canonical, the JSON Schema files serve as the documentation contract, and the small stdlib validator enforces exactly the domain invariants needed (identity agreement, shapes, known acyclic supersedes, containment). Refusing a committed shared index removes the parallel-agent merge-conflict class by construction.

## Decision / result
Keep `immutable per-run records -> schema/integrity validation -> derived catalog/query -> curated topic notes`. Agents discover via `python automation/knowledge_catalog.py query ...` and read only relevant full records; generated output goes to stdout or an explicit temp/cache path, never into the repository.

## Validation
- `python3 automation/knowledge_catalog.py validate` reports `ok` with 6 records (including this one).
- `python3 automation/knowledge_catalog.py build` twice produces byte-identical JSON; query filters and composed filters verified.
- `python3 -m pytest -q`: 268 passed.
- `git status --short` confirms no generated hot-file index and no `.github/workflows/**` changes.

## Reusable knowledge
- Discovery before reading: run the catalog `query` first, then open only matching full records; the catalog never replaces a record as evidence.
- Front matter is strict JSON parsed with `json`; filename, `issue`, `run_id`, and `record_id` must agree or validation fails closed.
- Never commit a generated catalog file; `build` defaults to stdout for exactly this reason.

## Unresolved questions / next experiment
